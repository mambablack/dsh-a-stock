# 验收：完整交易日演练 与 提案落实流程

## 一、完整交易日演练

真实交易日里，策略可能连续几天不出信号，交易腿（买入→盯盘→卖出）就一直没被验证。
`scripts/rehearse_day.py` 用确定性价格把整条命令链跑一遍，**每一步都判 PASS/FAIL**：

```powershell
python scripts\rehearse_day.py
```

它做的事（全部用真实脚本、真实账本格式，不碰主账户）：

| 步骤 | 命令 | 判定 |
|---|---|---|
| 1 | `paper.py init --capital 1000000` | 账户创建 |
| 2 | `paper.py buy ... --stop 4.40 --target 6.50 --strategy PB-001` | 建仓成功、T+1 记今日建仓 |
| 3 | 把建仓日改成昨天 | 模拟"第二天" |
| 4 | 价格 6.55 → `monitor.py --once --prices` | 触发 `target`、告警落盘 |
| 5 | `paper.py sell ... @6.55` | 卖出成功、成本/费用正确 |
| 6 | `paper.py check` | 对账通过 |
| 7 | `paper.py status` | 权益 1,015,322（+1.53%） |
| 8 | `paper.py history` | 买卖两笔 + 盈亏齐全 |

**2026-11-16 实测：8/8 通过。**

演练账户在 `data/rehearsal/`（已被 .gitignore 忽略），可随时删除重跑。

## 二、提案：批准 → 落实

```
pending --(人类 decide --approve)--> approved --(Agent apply)--> applied
```

```powershell
python scripts\propose.py list
python scripts\propose.py decide --id PROP-20261116-02 --approve --note "批准，先纸面跟踪"
python scripts\propose.py apply  --id PROP-20261116-02 `
  --change "PB-002 状态 candidate → tracking，allocation weight 0.3" `
  --regression "未跑（只改状态，无需回测）" `
  --commit "<commit hash>"
```

约束：

- **没收到的批准不能落实**：`apply` 会检查状态，`pending`/`rejected` 直接拒绝；
- **落实必须留痕**：会往提案文件追加「落实记录」（日期、变更、回归回测 run id、commit hash）；
- **风险层改动只有人类能批**（`risk.json` / `allocation.json` 的权重、持仓数、熔断阈值）；
- 落实后跑 `intake.py check` + `propose.py check` + `git commit`，三件事缺一不可。

`propose.py check` 同时保证：journal/handover/index/plans 里引用的每个提案编号都真实存在，
且格式统一为 `PROP-YYYYMMDD-NN`——防止 Agent 凭记忆编号。
