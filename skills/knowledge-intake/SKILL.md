# 知识入库（knowledge-intake）

你的任务不是"记住用户说了什么"，而是**把一段自然语言变成可以被检验的东西**。

## 一、先分类（决定后续动作）

| 类型 | 特征 | 动作 |
|---|---|---|
| A 可交易规则 | 有明确的买点/卖点/选股条件 | 入库 + 生成假设卡 + 排回测 |
| B 复盘教训 | "这次亏损是因为…" | 入库 + 提取「检查清单条目」 |
| C 市场观察 | "小市值在 12 月容易炒" | 入库 + 判断能否用历史数据检验 |
| D 书摘/理念 | 无具体参数 | 入库，标注「暂不可测」 |
| E 噪音/重复 | 与已有条目冲突或重复 | 不入库，说明原因并指出冲突对象 |

**不要把 D 类硬包装成规则。** "纪律比技术重要"这种话进知识库可以，但不能变成交易条件。

## 二、入库流程

1. **原文先落盘**（一字不改）：
   `trader/memory/knowledge/YYYY-MM-DD-<短标题>.md`

```markdown
---
id: K-20261115-001
date: 2026-11-15
source: 用户飞书输入
type: A            # A规则 / B教训 / C观察 / D理念 / E重复
tags: [均线, 趋势, 择时]
testable: true     # 是否能被历史数据检验
---

## 原文
> （用户原话，一字不改）

## 结构化
- 适用市场/周期：
- 买入条件：
- 卖出条件：
- 隐含参数：
- 无法量化的部分：

## 我的翻译（可执行版）
- 条件树草案：
- 对应 strategy-lab 特征：

## 检验计划
- 回测策略 id：
- 期望验证什么：
```

2. **更新索引**：在 `trader/memory/index.md` 加一行（id / 日期 / 标题 / 类型 / 状态）。
3. **若可测**：在 `trader/memory/playbook/` 建一张**候选**卡（模板见`docs/02-进化机制.md`），状态 `candidate`。
4. **排队**：在 `trader/memory/index.md` 的「待办」里写一条「回测 K-xxx」。

## 三、冲突与去重

- 新条目与已有打法矛盾时：**不覆盖**，在两侧都加 `conflicts: [PB-xxx]`，并说明冲突点。
- 重复条目：返回「与 K-xxx 重复」，只在原条目补一句来源。
- 用户明确说"以后都按这个来"：仍要入库+回测，**不能直接改打法**——除非是人类批准过的提案。

## 四、回测完成后

把结论写回知识条目：

```markdown
## 检验结果（YYYY-MM-DD）
- 回测：runs/<run-id>（样本内外、笔数、期望、盈亏比、回撤）
- 结论：支持 / 部分支持 / 证伪 / 样本不足
- 升级：PB-xxx 状态 candidate → tracking（纸面跟踪 N 笔）
```

## 五、回复用户的模板

```
已入库：K-20261115-001《标题》（A 类，可测）
- 我把它拆成了 3 个条件：…
- 对应特征：… ；需要补的特征：…
- 下一步：跑回测验证（约 1 分钟），完了我把结论写回这张卡
```

如果不可测：

```
已入库（D 类，暂不可测）：这句话没有可执行条件，我不会拿它改交易规则。
但可以作为「复盘检查清单」的第 N 条，用在每周复盘里。
```

## 六、纪律

- 用户的原话必须保留，不许润色成"更合理"的版本。
- 没有回测/纸面证据之前，任何知识都只是**候选**，不得用于实盘决策。
- 一条知识最多对应一张打法卡；拆得太碎会让复盘无法归因。
